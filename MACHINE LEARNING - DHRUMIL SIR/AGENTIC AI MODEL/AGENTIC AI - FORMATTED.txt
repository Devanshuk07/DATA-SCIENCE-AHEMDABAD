SESSION 1 :- 1. Evaluate prompt engineering, RAG, and fine-tuning for a
food delivery chatbot recommending dishes using dietary restrictions,
order history, and real-time menu availability. Recommend a suitable
approach or combination and explain why the alternatives are less
suitable.

2.  Explain what LoRA modifies in a pre-trained model compared with full
    fine-tuning, why it uses less VRAM, and what trade-off is accepted
    when using it on a consumer GPU with 8 GB VRAM.

3.  A fine-tuned complaint classifier performs well on common complaints
    but fails on rare complaints absent from its 6,000 labelled training
    examples. Identify two fundamental limitations of fine-tuning. For
    each, recommend re-fine-tuning with more data, RAG, or few-shot
    prompting, and state the condition under which the remedy is valid.

4.  Trace the request “Order 2 portions of Masala Dosa from Saravana
    Bhavan for delivery at 7 PM tonight” using the Perceive → Think →
    Act loop. Explain what is perceived, what reasoning and ambiguity
    resolution occur, which tools are called and in what order, and how
    the loop continues if the restaurant is unavailable at 7 PM.

5.  Design a Database MCP Server for food-delivery support and
    analytics. Name the tools to expose (e.g. list_tables,
    describe_table, run_select_query), choose read-only or read-write
    access and justify it, give a realistic delayed-order question, and
    explain a safeguard that prevents unnecessary sensitive data from
    being returned.

6.  For a food-delivery support agent using the ReAct pattern, handle:
    “My order #FD4521 was 40 minutes late and the food arrived cold. I
    want either a full refund or a significant discount on my next
    order.” Walk through at least two complete Reason → Action →
    Observation cycles, stating the reasoning, tool action, and
    observation in each. Explain why separating reasoning from action
    matters for financial decisions.

SESSION 2 :- 1. Task 1: AI Technique Decision Engine

Build a Python function recommend_technique(update_frequency,
data_in_external_docs, needs_custom_behaviour, latency_budget) accepting
update_frequency (‘high’/‘low’), data_in_external_docs (‘yes’/‘no’),
needs_custom_behaviour (‘yes’/‘no’), and latency_budget (‘low’/‘high’).

Requirements: - Use a decision tree to map inputs to Prompt Engineering,
RAG, or Fine-Tuning, with at least five distinct rule paths. - Return a
dictionary with keys ‘technique’ and ‘justification’; the justification
must be two sentences. - Test at least four food-delivery scenarios
(e.g. real-time menu recommendations, complaint categorisation, order
confirmation messages, and domain-specific FAQ answering) and print each
recommendation.

2.  Task 2: Tool-Calling Delivery Agent

Build a Python class FoodDeliveryAgent that routes customer queries to
the correct internal tool and executes it.

Requirements: - Define check_restaurant_status(name),
get_estimated_delivery_time(order_id), apply_discount(order_id, reason),
and file_complaint(order_id, issue) outside the class; each returns a
formatted string. - Define an MCP-style schema dictionary for each tool
with keys name, description, and parameters. Print all four schemas once
before test queries. - Implement FoodDeliveryAgent.think(query) to parse
keywords and map queries to the correct tool. - Record each (query,
tool_called, result) tuple in an internal log list. - Test at least five
varied queries covering all four tools, and print outputs and the
session log.

3.  Task 3: Memory-Aware Strategy Selector

Build an agent with prompt_template_response(query),
rag_lookup_response(query), and fine_tuned_response(query), each
returning a simulated relevant food-delivery response.

Requirements: - Maintain memory keyed by user_id with interaction_count,
preferred_cuisine, and last_complaint (initially None), updating it
after every interaction. - Implement decide_strategy(user_id, query):
select fine-tuned for complaint queries after 3+ interactions, RAG for
menu/item queries, and prompt template otherwise; return strategy and
response. - Simulate at least five interactions for the same user_id,
show strategy changes, and print memory after each interaction.

4.  Task 4: Multi-Agent Order Lifecycle System

Build a console-based system with OrderAgent, DispatchAgent, and
SupportAgent classes, each with process(data). OrderAgent creates an
order summary; DispatchAgent assigns a partner and ETA from a simulated
list; SupportAgent classifies feedback as positive, complaint, or
escalate and selects prompt, RAG, or fine-tuned response technique.

Requirements: - Create Coordinator.run_lifecycle(customer_input,
feedback), passing outputs in order OrderAgent → DispatchAgent →
SupportAgent and collecting each output. - Print a structured report
with order summary, dispatch details, feedback classification,
technique, and simulated processing time. - Run at least two scenarios
(e.g. smooth delivery and complaint) and demonstrate different technique
selections.

SESSION 3 :- 1. Mini Project: Agentic Food Delivery Assistant

Build a console-based multi-tool AI agent for a food-delivery platform
integrating technique selection, tool calling, per-session memory, and
ReAct-style reasoning.

Requirements: - Provide menu options: (1) Place Order, (2) Track Order,
(3) File Complaint, (4) Get Personalised Recommendations, and (5) Exit;
exit prints a session summary. - Each of the first four options invokes
place_order(), track_order(), file_complaint(), or
get_recommendations(). Log each tool call, arguments, and result in
session_log. Define and print an MCP-style schema (name, description,
parameters) for every tool before the menu loop. - Maintain
session_memory with orders_placed, complaints_filed, preferred_cuisine,
and interaction_count, updating it after every menu action. - Call
decide_response_strategy(action_type, memory) for every action. It
returns prompt, rag, or fine_tuned based on action type and memory;
print the strategy with the tool result. - On exit, print actions in
order, the tool and strategy used for each, and final session_memory.

SESSION 4 :- 1. AI-AUGMENTED LEARNING

STEP 1 — BUILD WITH AI

Write a Python program implementing a simplified ReAct (Reason + Action)
loop for a food-delivery customer-support agent processing a complaint.

Requirements: - Execute at least two complete Reason → Action →
Observation cycles before the final response, printing each cycle’s
thought, action call, and observation. - Include at least two callable
tools, such as lookup_order_status(order_id) and
check_refund_eligibility(order_id), invoked during the action step. -
Handle a tool error or ‘not found’ result and use that observation in
the next reasoning step instead of crashing.

STEP 2 — TEST & DEBUG (WITHOUT AI)

Test independently, identify at least one bug, limitation, or
improvement in the AI-generated solution, and fix it yourself.

SUBMISSION REQUIREMENTS: - Exact prompt(s) given to the AI tool. - AI’s
original code and corrected version. - A 3–4 line note explaining what
changed and why it was needed.
