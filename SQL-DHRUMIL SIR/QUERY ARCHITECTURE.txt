QUERY ARCHITECTURE:-

INSERT INTO TABLE-NAME() VALUES()
AFTER WRITTING QUERY WE CLICK GO BUTTON.
IT GIVES ERROR OR OUTPUT.

WHAT HAPPEN INTERNALLY ?
USER QUERY-->

1)PARSER (CHECK SYNTAX,IF SYNTAX WRONG NO FORWARD GOING,JUST GIVE ERROR.)

2)ANALYZER
-Checks whether the query is valid logically/semantically.
-Checks things like:
-Does the table exist?
-Do the columns exist?
-Do you have permission?
-Are the operations valid?

3)OPTIMIZER (CHOOSE BEST PLAN TO EXECUTE QUERY)
-QUERY PERFORMANCE CHECK USER INPUT.IF INDEX GIVEN OR NOT.IF GIVEN THEN IS THAT IN ROW OR COLUMN MEANS I HAVE TO TAKE ONLY ROW OR COLUMN.ACCOURING TOO YOUR GIVEN CONDITION.
-IN WHICH FORM DO I HAVE TO GIVE OUTPUT TO USER.

4)EXECUTION ENGINE(WHAT TO DO)
-Executes the execution plan given by the optimizer.
-It coordinates with the storage engine to actually retrieve/modify data.

👉 "Run the plan."

5)STORAGE ENGINE (ACTUAL ACCESS THE DATA)
-Actually handles the data stored in the database.
-Reads/writes data from storage.
-For example, in MySQL, InnoDB is a storage engine..

-FINAL RESULT.
